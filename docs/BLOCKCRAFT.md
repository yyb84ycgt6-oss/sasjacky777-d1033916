# BlockCraft

`/craft` (also `/minecraft`, and **Games & Worlds → ⛏️ BlockCraft** in the
sidebar) is a block-building survival game in the tradition of Minecraft:
survival, creative and hardcore; mining, crafting, smelting, farming; mobs,
water and lava, TNT, beds, day and night, weather; saves on the device, in a
file or in the cloud; 24 advancements to earn; and multiplayer online or
between tabs. It is an original
work — every texture, model and sound is generated by code in `src/craft`, so
there are no asset downloads, nothing licensed from Mojang, and the game works
offline once the page has loaded.

## Layout

```
src/craft/
  engine/   the world, independent of any screen: blocks, items, textures (painted
            procedurally), noise, worldgen, lighting, meshing, physics, mobs,
            block rules (fluids, crops, falling blocks), crafting, explosions.
            Runs in the browser, in workers and in vitest alike.
  render/   three.js: chunk meshes on a custom shader, sky, clouds, weather,
            particles, entity models, the first-person hand.
  game/     the running game: the 20-tick loop, actions (mining, placing, using),
            chunk streaming, input, commands, containers, saves, cloud saves.
  net/      multiplayer: transports (Supabase Realtime, BroadcastChannel) and
            the host/guest session.
  ui/       React over the canvas: title, worlds, HUD, inventories, menus,
            touch controls.
  audio.ts  synthesised sound effects and music.
src/pages/BlockCraft.tsx   the route
supabase/migrations/20260923120000_craft_worlds.sql   cloud saves
```

The game loop never goes through React. `Game` owns the world and the frame;
the UI reads a small store (`game/store.ts`) the game updates ten times a
second, plus on every inventory change.

## Two ways to play

**Desktop**: WASD, space, shift to sneak, ctrl or double-tap W to sprint, E
inventory, Q drop, T or / chat, 1–9 and the wheel for the hotbar, F1 hide HUD,
F2 screenshot, F3 debug, F5 camera, middle click to pick a block, double-tap
space to fly in creative. The mouse is captured while playing; every screen
releases it (see `src/test/craft-input.test.ts` for why each rule exists).

**Touch**: chosen automatically on touch devices (Options → Controls to
change). A joystick appears under the left thumb, dragging anywhere else looks
around, and buttons jump, sneak, mine and place — or "Tap to interact": tap to
place or use, hold to mine. Inventories have a quick-move toggle in place of
shift-click, and a long press is a right click.

## Commands

With cheats on (a world option) or in creative: `/time`, `/gamemode`, `/give`,
`/tp`, `/weather`, `/summon`, `/effect`, `/xp`, `/setblock`, `/fill`, `/kill`,
`/clear`, `/spawnpoint`, `/difficulty`, `/gamerule`; `/seed` and `/help` for
everyone. An online guest cannot run the ones that change the shared world.

## Saving

Worlds live in IndexedDB — only chunks that were changed are stored, gzipped.
The game saves every 30 seconds, when the tab is hidden, and on quit. If
IndexedDB is unavailable (some private modes) the game says so on screen and
keeps the world in memory; export it to keep it.

The world list exports a world to a `.blockcraft.json` file and imports one
back. **Upload to Cloud** stores that same file in `craft_worlds`, owner-only
under RLS; **Cloud Worlds…** lists and downloads them on any device signed in
to the same account. The table arrives with `supabase db push` — until then
the cloud buttons say exactly that, and nothing else is affected.

## Multiplayer

The host owns the world. Esc → **Open to friends** gives a six-letter code;
friends use **Multiplayer**, type it and join. "Online" goes through Supabase
Realtime broadcast channels (`blockcraft:<code>`); "Tabs on this device" uses a
BroadcastChannel and needs no network at all.

Guests generate untouched terrain from the seed themselves and fetch only
chunks the host reports as modified. Block edits are applied at once where they
are made, sent to the host, numbered and rebroadcast, so every client converges
on the host's order; edits for a chunk still loading are held and replayed
after it arrives. Mobs, water, time and weather run only on the host. A host
keeps ticking in a background tab (browsers stop animation frames there), and
a guest's inventory is stored in the host's world under the guest's
browser-stable id, so it is still there when they rejoin.

## Checking a change

```
npx vitest run src/test/craft-*      # engine, gameplay, input rules, cloud saves
npx tsc --noEmit -p tsconfig.app.json
```

In a development build the running game is `window.__blockcraft`, which is
how the browser checks during development read positions and screens.
